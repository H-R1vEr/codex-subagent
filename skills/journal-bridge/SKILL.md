# 期刊技能桥接 / journal-bridge

## Input contract

Use the user's actual artifacts, purpose and permitted output location. Identify missing inputs that affect the result; label assumptions. Instructions are a workflow, not an embedded numerical engine. Install or use scientific software only when needed and available. Preserve originals and distinguish observed, simulated and historical evidence.

## Workflow

1. Identify target journal, article type and requested task. Read installed skill names/descriptions and select the relevant journal skill only if available; do not invent an upstream skill name.
2. Read the selected installed SKILL.md. Treat it as optional guidance subject to user scope and actual evidence, not permission to publish, email or fabricate results.
3. If absent, explain how to install an independently reviewed upstream package using the repository integration guide. Continue evidence-based research work that does not depend on that package.
4. Verify current publisher author instructions and record URL/date before stating word limits, reporting requirements or submission rules. Package summaries may be stale and are not journal endorsement.
5. Resolve conflicts in favor of verified current requirements and scientific accuracy. Report requirements that are unchecked; do not copy upstream skill text into this repository.

## Deliverable

Selected installed skill or explicit absence; current author-guideline sources/date; research-to-journal task mapping; unmet requirements and license/source notes.

Include source locators and environment/method details needed to check the result. State the weakest evidence and the largest remaining gap; use “none identified” when applicable.

## Acceptance scenario

No Cell skill is installed: do not claim it was invoked. A journal package asks for unsupported novelty: preserve the evidence boundary.
