# 审稿视角审计 / reviewer-audit

## Input contract

Use the user's actual artifacts, purpose and permitted output location. Identify missing inputs that affect the result; label assumptions. Instructions are a workflow, not an embedded numerical engine. Install or use scientific software only when needed and available. Preserve originals and distinguish observed, simulated and historical evidence.

## Workflow

1. State manuscript scope and available artifacts. Summarize the contribution accurately before assessing it; do not assume a high-impact venue is appropriate.
2. Review design, sampling, method assumptions, uncertainty, baselines, leakage and claim support. Anchor each concern to a section, figure, equation, table or missing artifact.
3. Separate fatal validity issues, major repairable concerns and minor presentation issues. Explain scientific consequence and the minimum analysis or wording change needed.
4. Treat novelty and external source checks as provisional unless verified. Do not invent references or pretend to represent an actual journal reviewer.
5. Balance strengths with limitations using evidence. Respect audit-only boundaries; present a reasoned readiness assessment rather than guaranteed acceptance.

## Deliverable

Evidence-grounded assessment; prioritized major/minor issues with locators, consequences and executable repairs; unchecked areas and readiness limits.

Include source locators and environment/method details needed to check the result. State the weakest evidence and the largest remaining gap; use “none identified” when applicable.

## Acceptance scenario

A reported high accuracy comes from randomly splitting records from the same events: identify leakage and recommend held-out-event evaluation.
